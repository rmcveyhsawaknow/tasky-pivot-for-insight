## API Endpoints

| Method | Route | Handler | Auth Required |
|--------|-------|---------|---------------|
| GET | `/` | `index` (inline) | No |
| POST | `/signup` | `controller.SignUp` | No |
| POST | `/login` | `controller.Login` | No |
| GET | `/todo` | `controller.Todo` | Yes (cookie) |

| GET | `/todo/:id` | `controller.GetTodo` | Yes (cookie) |

- **Non-root user (image):** `appuser:appgroup` (UID/GID 1001) — defined in `Dockerfile`
- **Non-root user (K8s override):** `runAsUser: 65534` (`nobody`) — set in `deployment.yaml` `securityContext`, overrides the image default at runtime
- **Working directory:** `/app`
- **Artifacts copied:** `/app/tasky` (binary), `/app/assets/`, `/app/exercise.txt`
- **Exposed port:** `8080`
- **Entrypoint:** `["/app/tasky"]`
- **Health check:** `wget --no-verbose --tries=1 --spider http://localhost:8080/health` (interval 30s, timeout 10s, retries 3) — **note:** the Go app does not define a `/health` route in `main.go` (only `/` is implemented and used by K8s liveness/readiness probes), so this Dockerfile health check currently targets a non-existent endpoint and should not be assumed to work.

    alb.ingress.kubernetes.io/target-type: ip
    alb.ingress.kubernetes.io/backend-protocol: HTTP

## Migration Prerequisites and Technical Debt

The following items must be resolved before or during the Azure migration to avoid blocking deployment or introducing security risk.

### 1. Unmaintained JWT Library (Security Risk)

`github.com/dgrijalva/jwt-go v3.2.0` is **unmaintained** and carries known security vulnerabilities (CVE-2020-26160). It must be replaced before production deployment on Azure.

**Action required:** Migrate to `github.com/golang-jwt/jwt` (the officially maintained fork). This is an in-code change limited to `auth/auth.go` and `go.mod` / `go.sum`.

### 2. Hardcoded Database Name (Migration Blocker)

The database name `go-mongodb` is hardcoded in `database/database.go:56` and is not configurable via environment variable:

```go
func OpenCollection(client *mongo.Client, collectionName string) *mongo.Collection {
    return client.Database("go-mongodb").Collection(collectionName)
}
```

**Action required:** Externalise the database name to an environment variable (e.g. `MONGODB_DATABASE`) before migrating the data tier. Azure Cosmos DB for MongoDB may use a different database name, and the current code cannot accommodate that without a code change.

### 3. MongoDB 4.0.x End-of-Life (Version Compatibility)

MongoDB 4.0.28 reached end-of-life in **April 2022** and is no longer receiving security patches. The current deployment uses this version by design (per the Insight Technical Exercise requirements).

**Action required during migration:** Evaluate the target MongoDB API compatibility for the chosen Azure service:

| Target Service | Supported MongoDB Wire Protocol | Notes |
|---------------|--------------------------------|-------|
| Azure Cosmos DB for MongoDB (vCore) | 5.0 / 6.0 | Recommended; full wire-protocol compatibility |
| Azure Cosmos DB for MongoDB (RU) | 3.6 / 4.0 | RU model; 4.0 support available |
| Azure VM (self-managed) | Any version | Allows in-place upgrade to 6.0+ |

A MongoDB version upgrade will be required regardless of target service; test application queries against the target version before cutover.
