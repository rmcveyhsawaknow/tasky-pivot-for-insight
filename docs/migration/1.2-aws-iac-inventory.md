## Provider Configuration

| Provider | Source | Version Constraint | Configuration |
|----------|--------|--------------------|---------------|
| AWS | hashicorp/aws | ~> 5.0 | Region from `var.aws_region`; default tags from `local.common_tags` |
| Kubernetes | hashicorp/kubernetes | ~> 2.20 | Connects to EKS cluster endpoint with OIDC token authentication |
| Helm | hashicorp/helm | ~> 2.10 | Configured via same EKS cluster endpoint and auth |

The Kubernetes and Helm providers dynamically source their configuration from the EKS cluster outputs (`cluster_endpoint`, `cluster_certificate_authority_data`) using an `exec`-based token retrieval (`aws eks get-token`).

## Migration Considerations

### AWS-Specific Resources Requiring Azure Equivalents

| AWS Resource | Terraform Resource Type | Azure Equivalent |
|-------------|------------------------|------------------|
| VPC | `aws_vpc`, `aws_subnet` | Azure Virtual Network, Subnets |
| Internet Gateway | `aws_internet_gateway` | Implicit in Azure VNet |
| NAT Gateway | `aws_nat_gateway`, `aws_eip` | Azure NAT Gateway |
| EKS Cluster | `aws_eks_cluster`, `aws_eks_node_group` | Azure Kubernetes Service (AKS) |
| EKS Add-ons | `aws_eks_addon` (vpc-cni, coredns, kube-proxy, ebs-csi) | AKS built-in add-ons |
| OIDC Provider | `aws_iam_openid_connect_provider` | AKS Workload Identity |
| IRSA | `aws_iam_role` + OIDC trust | AKS Workload Identity Federation |
| EC2 Instance | `aws_instance` | Azure Cosmos DB for MongoDB (PaaS) or Azure VM |
| S3 Bucket | `aws_s3_bucket` | Azure Blob Storage |
| IAM Roles | `aws_iam_role`, `aws_iam_policy` | Azure Managed Identity, RBAC |
| CloudWatch Logs | `aws_cloudwatch_log_group` | Azure Monitor / Log Analytics |
| VPC Endpoints | `aws_vpc_endpoint` | Azure Private Endpoints |
| ALB | `aws_lb` (commented out) | Azure Application Gateway / AGIC |
| Route53 | `aws_route53_record` (commented out) | Azure DNS |

### State Backend Migration

The production Terraform state backend uses AWS S3 + DynamoDB. For the Azure migration, consider:

- **Azure Storage Account** with blob container for state storage
- **Azure Storage blob lease** for state locking (built into the `azurerm` backend)
- Migration path: new Terraform root with `azurerm` backend, not a state migration

### Security Observations for Migration

- MongoDB EC2 instance has `AdministratorAccess` IAM policy — apply least-privilege in Azure
- S3 bucket allows public read access — evaluate whether Azure Blob public access is required
- `mongodb_password` and `jwt_secret` have hardcoded defaults — use Azure Key Vault during migration
- EKS cluster version 1.28 — map to equivalent AKS Kubernetes version
